# DeepSeek 算子使用情况对比：NVIDIA vs MetaX(沐曦) vs Hygon(海光)

> 基于 vLLM plugin-fl 项目，对比 DeepSeek V2/V3 在不同硬件平台上的算子实现差异。
> plugin-fl 项目路径：`/Users/baai/Desktop/baai_proj/vllm-plugin-FL`

## 调度机制说明

plugin-fl 使用三级后端调度机制，按优先级顺序尝试：

| 后端名称 | 说明 |
|---------|------|
| **flagos** (FlagGems) | 基于 Triton 的通用实现（`flag_gems` 库） |
| **vendor** | 厂商专用实现（MetaX: MACA 库, Hygon: vLLM HIP 原生算子） |
| **reference** | PyTorch 原生实现（兜底） |

配置文件：
- MetaX: `vllm_fl/dispatch/config/metax.yaml`
- Hygon: `vllm_fl/dispatch/config/hygon.yaml`

## 全量算子对比表

### 1. Embedding Lookup

| 平台 | 实现方式 | 来源 |
|------|---------|------|
| NVIDIA | PyTorch `nn.Embedding` (VocabParallelEmbedding) | vLLM 原生 |
| MetaX | **同上** — 无替换 | 透传 |
| Hygon | **同上** — 无替换 | 透传 |

### 2. RMSNorm (`fused_add_rms_norm`)

| 平台 | 实际执行路径 | 实现类型 | 配置优先级 |
|------|------------|---------|-----------|
| NVIDIA | `csrc/layernorm_kernels.cu` | Custom CUDA | 原生 |
| MetaX | `flag_gems.modules.normalization.gems_rms_forward` | **Triton** (FlagGems) | flagos → reference |
| Hygon | `flag_gems.modules.normalization.gems_rms_forward` | **Triton** (FlagGems) | flagos → reference |

备注：两平台均有 vendor 实现（调用 vLLM 原生 CUDA/HIP kernel），但 YAML 中 vendor 被注释，实际走 FlagGems。

### 3. SiluAndMul 激活函数

### 4. RoPE 旋转位置编码

### 5. Attention Kernel（核心注意力计算）

| 平台 | Prefill | Decode | 实现类型 |
|------|---------|--------|---------|
| NVIDIA | Flash Attention (`flash_attn_varlen_func`) | FlashMLA / Triton / CUTLASS MLA | C++/CUDA + Triton |
| MetaX | MACA Flash Attention / Triton MLA | MACA FlashMLA / Triton MLA | MACA C++/CUDA 或 Triton |
| Hygon | Triton MLA (reference) | Triton MLA / ROCm AITER MLA | Triton + ROCm HIP |

MetaX 说明：
- 有完整的 `MacaFlashAttentionBackend`（~1200行），位于 `vendor/metax/impl/attention/flash_attn.py`
- 使用 MACA SDK 的 Flash Attention + FlashMLA
- **当前 YAML 中 vendor:metax 被注释**，实际走 reference（Triton MLA）

### 15. Sampling（Top-K / Top-P）

| 平台 | 实际执行路径 | 实现类型 |
|------|------------|---------|
| NVIDIA | PyTorch (`torch.topk`, `torch.multinomial`) | PyTorch |

## 关键差异总结

### MetaX (沐曦) 平台特点

1. **几乎所有 Custom CUDA kernel 被 FlagGems Triton 替代** — RMSNorm, SiLU, RoPE, MoE 全系列
2. **Triton 编译有限制** — Sampling kernel 失败被 patch；`masked_fill` 被黑名单
3. **关闭第三方 Triton kernels** — `has_triton_kernels = lambda: False`；禁用 cascade attention, cuDNN, TRT-LLM, FlashInfer
4. **有 MACA 专用 attention backend**（功能完整但当前被注释）
5. **不支持 FP8 优化路径**（无 DeepGemm / CUTLASS）

### Hygon (海光) 平台特点

1. **默认路径与 MetaX 一致：FlagGems Triton 优先**
2. **保留 vendor 降级路径** — `grouped_topk`, `moe_align`, `moe_sum` 有 HIP 备选
3. **Attention 走 Triton MLA 或 ROCm AITER**
4. **大部分 vendor 路径在 YAML 中被注释**（实际 FlagGems 优先）
5. **不支持 FP8 优化路径**

### 预计性能影响

| 组件 | NVIDIA 最优实现 | MetaX/Hygon 替代 | 影响程度 |
|------|---------------|-----------------|---------|
| MoE GEMM | DeepGemm (FP8) / CUTLASS | FlagGems Triton (BF16) | **高** — 失去 FP8 加速 |
| Attention Decode | FlashMLA (专用 CUDA) | Triton MLA | **中** — 通用 Triton 略慢 |
| RMSNorm | Fused CUDA kernel | FlagGems Triton | **低** — 访存密集，差距小 |
| RoPE | C++ kernel | FlagGems Triton | **低** — 计算量小 |
| Sampling | PyTorch | PyTorch | **无** |
