# vLLM 平台依赖架构

本文梳理 vLLM 中所有依赖设备平台的模块，覆盖平台抽象、算子、注意力后端、计算图捕获、显存管理、通信、Worker 等维度。

---

## 一、平台抽象层 — `vllm/platforms/`

这是整个平台调度的核心。通过 `Platform` 基类 + 自动检测机制，决定运行时使用哪套实现。

| 文件 | 平台 | 通信后端 |
|------|------|----------|
| `cuda.py` | NVIDIA CUDA | NCCL |
| `rocm.py` | AMD ROCm | RCCL (兼容 NCCL 接口) |
| `xpu.py` | Intel XPU | XCCL |
| `tpu.py` | Google TPU | 外部实现 (tpu_inference) |
| `cpu.py` | CPU (x86/ARM/RISC-V/PowerPC) | Gloo |
| `zen_cpu.py` | AMD Zen CPU (CpuPlatform 子类) | Gloo |
| `interface.py` | 基类 `Platform` + `PlatformEnum` + `CpuArchEnum` | — |

**检测优先级**: OOT 插件 > TPU > CUDA > ROCm > XPU > CPU > Unspecified

**核心方法**:
- `get_attn_backend_cls()` — 选择注意力后端
- `get_device_capability()` — 查询设备能力
- `init_distributed_environment()` — 初始化分布式环境
- `check_and_update_config()` — 校验和调整配置
- `import_kernels()` — 加载平台对应的算子库

**插件机制**: 通过 `vllm.platform_plugins` setuptools entry point，第三方可注册 OOT 平台。

**`csrc/cpu/`** (CPU 专用，多 ISA 后端):

**`csrc/mamba/mamba_ssm/`** (CUDA): Mamba 状态空间模型核

## 九、构建系统

`CMakeLists.txt` 通过 `VLLM_TARGET_DEVICE` 控制编译目标:

| 目标 | 说明 |
|------|------|
| `cuda` (默认) | 完整 CUDA 编译，按 GPU 架构选择核函数 |
| `rocm` | HIP 编译，通过 `cmake/hipify.py` 源码转换 |
| `cpu` | 委托给 `cmake/cpu_extension.cmake` |

XPU 和 TPU 的核函数在外部包 (`vllm_xpu_kernels`, `tpu_inference`) 中，不从本仓库构建。

支持的 ROCm 架构: gfx906, gfx908, gfx90a, gfx942, gfx950, gfx1030, gfx1100-gfx1201

## 十、整体架构关系

```
用户请求
  │
  ├─ Platform Detection (平台相关: vllm/platforms/)
  │    └─ 自动探测硬件 → 实例化 current_platform
  │         ├─ 设备能力查询 (get_device_capability)
  │         ├─ 算子库加载 (import_kernels)
  │         └─ 分布式环境初始化 (init_distributed_environment)
  │
  └─ Engine / Scheduler (平台无关)
       └─ Worker (平台相关)
            ├─ Device Management (平台相关)
            │    ├─ 设备初始化 (set_device, set_seed)
            │    ├─ 显存分配器 (device_allocator/cumem.py — cuMem API)
            │    └─ 显存 profiling (确定可用 KV Cache block 数)
            │
            ├─ ModelRunner (平台相关: 图捕获、内存布局)
            │    ├─ Attention Backend (平台相关)
            │    ├─ Custom Ops / Kernels (平台相关)
            │    └─ Compilation / CUDAGraph (平台相关)
            │
            ├─ KV Cache Manager (逻辑层平台无关, 分配器平台相关)
            │
            └─ Device Communicator (平台相关)
```

## 十一、平台覆盖总结

| 平台 | Worker | 注意力 | 通信 | 编译扩展 | 算子绑定 |
|------|--------|--------|------|----------|----------|
| **CUDA** | gpu_worker | FlashAttn, FlashInfer, Triton, Flex, 全部 MLA 变体 | NCCL, CustomAllReduce, QuickReduce, SymmMem | 完整 csrc/ | `_custom_ops.py`, `_oink_ops.py` |
| **ROCm** | gpu_worker (共用) | RocmAttn, AITER FA, AITER MLA, AITER Unified | NCCL (via rccl) | csrc/ (hipified) + csrc/rocm/ | `_aiter_ops.py` |
| **XPU** | xpu_worker | XPU MLA Sparse | XCCL | 外部 (vllm_xpu_kernels) | `_xpu_ops.py` |
| **TPU** | 外部 (tpu_inference) | 外部 | 外部 | 外部 | 外部 |
| **CPU** | cpu_worker | cpu_attn | Gloo | csrc/cpu/ | N/A |
| **Zen CPU** | cpu_worker | cpu_attn | Gloo | csrc/cpu/ + zentorch | N/A |
